│ ## Session S10 — Multi-Agent Orchestrator
│ 
│ **Architecture:** Python orchestrator (`app/orchestrator.py`) that routes questions to two specialist Cortex Agents + deterministic Verifier/Narrative procedures.
│ 
│ **What was created:**
│ 
│ | Object | Purpose |
│ |--------|---------|
│ | `EVIDENCE_AGENT` | Cortex Agent with Cortex Analyst (ARGUS_FRAUD_SV) + custom FN_TYPOLOGY_CARD tool |
│ | `POLICY_AGENT` | Cortex Agent with Cortex Search (POLICY_SEARCH) + Cortex Analyst (ARGUS_REGTWIN_SV) |
│ | `FN_TYPOLOGY_CARD` | UDF returning markdown typology cards |
│ | `AGENT_RUN_LOG` | Handoff log table (run_id, step, from/to agent, refs, timing) |

│ | `sql/13_agents.sql` | All DDL in one deployable file |
│ 
│ **Key design decision:** Cortex Agents support `agent_toolset` (tool inheritance), but NOT sub-agent routing. The orchestrator is Python because: (1) the Verifier is deterministic SQL, not an LLM; (2) different specialists need different sub-questions; (3) the filing gate must be enforced before any narrative generation.
