### 2. Create `sql/10_typology_discovery.sql` — the main deliverable

**Tables:**
- `ARGUS.GOVERNED.TYPOLOGY` — discovered typologies (TYP-0001, etc.), with class, banks, member_count, value, confidence, detection_sql, card_md, status, discovered_at
- `ARGUS.GOVERNED.TYPOLOGY_CLASS` — from twin_seed.json `typology_classes`
- `ARGUS.GOVERNED.TYPOLOGY_CLASS_OBLIGATION` — from twin_seed.json `typology_class_obligation`

**Procedure `ARGUS.GOVERNED.SP_DISCOVER_TYPOLOGIES()`:**

1. **Transfer edges** (temp): all debit transactions where `counterparty_bank IN ('BANK_A','BANK_B','BANK_C')` — both intra-bank AND inter-bank. Resolve `counterparty_iban` → account_id via `RAW.ACCOUNTS.iban`. Filter `amount >= 10000`. Exclude `EXTERNAL`.

2. **Seeds** (temp): hub accounts (DT_HUB_ACCOUNTS), structuring (DT_STRUCTURING), shared national_id at ≥2 banks (BANK_IDENTIFIER_EXPOSURE × SHARED_BAD_ACTOR_SIGNAL), cross-bank edge participants (both sides of DT_CROSS_BANK_EDGES), open LIVE_ALERTS. Each seed carries an activity window.

3. **BFS expansion** (2 hops): from seeds, follow transfer edges bidirectionally. Edge must fall within ±7 days of seed's activity window. Two explicit INSERT passes (hop 1, hop 2), each with forward + backward direction.

4. **Identity expansion**: national_id links auto-join if counterpart is in a different bank. Device links join ONLY if the account also has a transfer edge to a community member.

5. **Community edges** (temp): transfer edges + national_id edges + filtered device edges, restricted to community members.

6. **Connected components**: iterative label propagation (`WHILE` loop in Snowflake Scripting) — each node's label ← MIN of its neighbor labels. Converges when `SQLROWCOUNT = 0`.

7. **Role assignment** per account:
   - `consolidation`: receives cross-bank from ≥2 other banks
   - `funnel`: receives same-bank AND sends cross-bank
   - `source_mule`: sends same-bank to funnel/consolidation only, no cross-bank activity
   - `layering_hop`: part of a 3-node cross-bank cycle
   - `structuring`: in DT_STRUCTURING
   - `shared_identity`: linked by cross-bank national_id/device, no other role

8. **Classification** per component: FAN_IN_FAN_OUT_MULE (has source_mule/funnel/consolidation), CIRCULAR_LAYERING (has layering_hop), SHARED_IDENTITY (only shared_identity), CASH_STRUCTURING (only structuring).

9. **Outputs**: DELETE existing DISCOVERED rows, then INSERT into TYPOLOGY and TYPOLOGY_EVIDENCE. Generate detection SQL per typology (template-based per class). Generate card_md via `SNOWFLAKE.CORTEX.COMPLETE('claude-sonnet-4-5', ...)` with JSON facts.

10. **Re-grant**: `GRANT SELECT ON TABLE ... TO ROLE ARGUS_ANALYST` for any CREATE OR REPLACE'd objects.
