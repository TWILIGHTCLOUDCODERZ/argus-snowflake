## Implementation Steps

### Step 1: Fix Typology ID Stability (`sql/10_sp_discover.sql`)
Modify the `_tm` table creation (line ~282-292) so that:
- Before assigning new IDs, snapshot the existing typology→member mapping (sorted entity_id list per typology_id).
- After computing new communities, match each new component's sorted member list against existing typologies.
- If a match: reuse that `typology_id`. If new: assign `TYP-NNNN` where NNNN = max existing + sequential.
- This ensures FINDING.typology_id remains valid across rediscovery runs.

### Step 2: Create Demo Wrapper Procedures (`sql/14_demo_wrappers.sql`)
Three **owner's-rights** procedures in `ARGUS.GOVERNED`:
- **`SP_DEMO_NEXT_BATCH()`**: Calls `ARGUS.RAW.SP_DELIVER_NEXT_BATCH()` then `ARGUS.GOVERNED.SP_RAISE_ALERTS()`. Returns batch result + alert count.
- **`SP_DEMO_REDISCOVER()`**: Calls `ARGUS.GOVERNED.SP_DISCOVER_TYPOLOGIES()`. Returns discovery result.
- **`SP_DEMO_RESET()`**: Calls `ARGUS.RAW.SP_RESET_LIVE_DEMO()`, deletes findings/filings for live-only typologies (those not in baseline), then calls `SP_DISCOVER_TYPOLOGIES()` to restore baseline. Returns status.
- Grant `USAGE` on all three to `ARGUS_ANALYST`.

### Step 3: Governance Grants for Streamlit
As ACCOUNTADMIN:
- `GRANT CREATE STREAMLIT ON SCHEMA ARGUS.GOVERNED TO ROLE ARGUS_ANALYST;`
- `GRANT CREATE STAGE ON SCHEMA ARGUS.GOVERNED TO ROLE ARGUS_ANALYST;` (for the app stage)
- Grant USAGE on the three demo wrapper procedures to ARGUS_ANALYST.
- Grant USAGE on SP_BUILD_FINDING, SP_VERIFY_FINDING, SP_DRAFT_FILING to ARGUS_ANALYST (needed for the orchestrator path).
- Grant UPDATE on FILING to ARGUS_ANALYST (for the "Approve draft" button).

### Step 4: Build Streamlit App (`app/streamlit_app.py`)
Single-file multi-page app using `st.sidebar` navigation (avoids the multi-file pages directory complexity in SiS). Five sections:

**1. Overview**
- KPI row: typology count by class, open live alerts count, control gaps by regulator
- Live Feed panel: "Deliver Next Batch" + "Reset Demo" buttons calling wrapper procedures
- Batch counter (from TXN_LIVE_QUEUE delivered count)
- Live alerts table appearing as batches are delivered

**2. Typologies**
- List: typology_id, class, banks, value, member_count, window
- Clicking a typology shows: card_md rendered as markdown, member table with roles/banks
- Ring diagram via `st.graphviz_chart` (source mules → funnels → consolidation, colored by bank)
- Detection SQL in an expander

**3. Finding**
- Claims table for selected finding: claim_type, claim_text, confidence, verified flag
- Selecting a claim: cited transactions (STRUCTURED_REFS joined to TRANSACTIONS, PII masked), cited clause text (CLAUSE_REFS joined to CLAUSE)
- Verifier status + reason prominently displayed

**4. Filing Review**
- Per-finding: list of filings (STR per bank + board memo)
- Narrative rendered as markdown
- Grounding check result displayed
- "Approve Draft" button: `UPDATE FILING SET approved_by = CURRENT_USER(), status = 'APPROVED'` — nothing sent

**5. Ask ARGUS**
- Chat interface using `st.chat_message` / `st.chat_input`
- Calls `orchestrate()` from the imported orchestrator
- Shows answer with citations
- Expandable handoff trace from `AGENT_RUN_LOG` for the run_id
