## Context

**Root cause of the two routing misses:**
1. "Do we need to report the mule network TYP-0003 to the regulator?" — matches both `_EVIDENCE_PATTERN` (contains "mule", "ring") and `_POLICY_PATTERN` (contains "regulat"). Routes to `combined` (evidence + policy), which never calls the Verifier. The user never gets a filing decision.
2. "Which rules does the cash structuring case break?" — "structuring" matches `_EVIDENCE_PATTERN` but "rules" and "break" don't match `_POLICY_PATTERN`. Routes to `evidence` only. The Policy agent (which knows CBUAE Art. 15 / SAMA Art. 12) is never called.

**Tested:** `AI_COMPLETE('claude-sonnet-4-5', ..., response_format => JSON schema)` correctly classifies both questions. Returns `{intents, typology_ids, account_ids}`.

## Implementation Steps

### Step 1: Broader PII detection (`orchestrator.py`)
Expand `_PII_PATTERN` to catch: national ID, passport, phone, email, date of birth, customer name/identity of the holder.

### Step 2: LLM intent classifier (`orchestrator.py`)
Add `classify_question_llm(cursor, question)` that calls:
```sql
SELECT SNOWFLAKE.CORTEX.AI_COMPLETE('claude-sonnet-4-5', <prompt>, <response_format>)
```
Returns `{"intents": [...], "typology_ids": [...], "account_ids": []}`.

The prompt tells the model about the three intents:
- `evidence` — transaction data, accounts, typology evidence, who/what/where
- `policy` — regulations, rules, obligations, controls, compliance, what law applies, what breaks/violates
- `filing_decision` — should we file/report, STR/SAR, notify regulator, is it reportable

### Step 3: Replace `classify_question` logic (`orchestrator.py`)
Keep the old regex classifier as `classify_question_regex()` (fallback). New `classify_question()` becomes:
1. **Deterministic refusal gates first** (PII, ungrounded) — unchanged but with broader PII regex
2. Call `classify_question_llm()`. On failure, fall back to `classify_question_regex()`.
3. **Hard safety rule** (deterministic, post-classification):
   - If `filing_decision` in intents, OR question matches reporting vocab regex (`file|filing|report|reportable|STR|SAR|FIU|GDFI|goAML|notify|disclose to regulator`), route includes Verifier → category = `file`
   - If question matches rules/regulations vocab (`rules|regulations|obligations|requirements|law|break|violate`), intents must include `policy`
4. Map the intents to a category: `file` if filing_decision present; `combined` if both evidence+policy; `policy` if policy-only; `evidence` as default.

### Step 4: Log classifier step (`orchestrator.py`)
In `orchestrate()`, after classification, log a handoff step:
```
from_agent="ORCHESTRATOR", to_agent="CLASSIFIER", output=JSON intents
```
This is step 0 (before any agent calls).

### Step 5: Post-agent safety net (`orchestrator.py`)
In the `combined` path, after agents respond, scan agent output for Verifier deferral phrases ("filing decisions are made by the Verifier", "cannot recommend filing"). If found, re-route to the filing path.

### Step 6: Update `validate_orchestrator.py`
